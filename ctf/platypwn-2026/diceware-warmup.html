Platypwn CTF 2026 — Diceware (Warmup) Write-up

Kategoriya: Cryptography / Web
Bosqich: Warmup (1-flag)
Holat: Yechilgan va CTF platformasida qabul qilingan
Flag: PP{yOu_4r3_7h3_5rv3r_n0w::ycF1hSK_GsIN}

Topshiriq

crypto.diceware.zip arxivi berildi. Unda Python/Flask asosidagi parol menejeri, Rust tilida yozilgan PIR (Private Information Retrieval) moduli va wordlist serverining kodlari bor edi. Maqsadimiz Warmup User hisobiga kirib, uning ichidagi warmup flag yozuvini olish edi.

Bu topshiriqda OSINT rasmi bo‘lmagan: asosiy dalillar ZIP ichidagi manba kodlari va ishga tushirilgan CTF xizmati edi.

Foydalanilgan vositalar

  • ZIP arxivi va manba kodlari: web/app/app.py, web/app/diceware.py, inspire/src/pir.rs, wordlist_server/src/main.rs
  • Termux — telefondan terminalga ulanish
  • Ubuntu VPS + WireGuard — CTF tarmog‘iga ulanish
  • Python 3 — PIR javob serveri va avtomatlashtirilgan sinov
  • HTTP so‘rovlari — parolni qayta o‘rnatish va login tekshiruvi

Yechim jarayoni

1. Koddan zaif nuqtani topish

web/app/app.py ichida POST /reset_password endpointi bor edi. U username va wordlist qiymatlarini qabul qilib, yangi parolni quyidagicha hosil qilardi:

new_password = generate_password(
    CLIENT_USERS,
    str(request.form.get("wordlist", DEFAULT_WORDLIST))
)

FlagUser uchun parolni qayta o‘rnatish taqiqlangan, ammo Warmup User uchun mumkin edi.

web/app/diceware.py esa so‘rovda berilgan wordlist manziliga POST yuborib, kelgan PIR javobini parol so‘ziga aylantirardi. Eng muhim kamchilik: wordlist URL foydalanuvchi tomonidan nazorat qilinardi; xizmat esa unga kelgan kriptografik javobga ishonardi.

2. PIR javobini boshqarish

Oddiy matn ko‘rinishidagi pebble javobi yetarli emas edi. Server to‘g‘ri Content-Type va PIR formatidagi shifrlangan javob kutardi.

Shu sabab diceware_pir_solution.py skripti yaratildi. U kelgan PIR so‘rovidan Paillier ochiq kalitining modulini (n) ajratib, pebble so‘zini kodlaydigan mos shifrlangan javob tayyorlardi. Javob Rust klienti kutadigan postcard formatiga keltirildi.

Skript ikki rejimda ishlardi:

python3 diceware_pir_solution.py serve --word pebble --port 9000

Keyin ikkinchi terminalda CTF'ning o‘sha vaqtdagi xizmati uchun:

python3 diceware_pir_solution.py solve \
  --base http://10.83.9.64:8081 \
  --callback http://10.82.1.33:9000/ \
  --word pebble

Izoh: IP manzillar CTF sessiyasiga tegishli edi; keyinchalik o‘zgarishi mumkin.

3. Parolni oldindan bilish

generate_password() har bir parolni 6 ta so‘zdan tuzardi. Bizning soxta PIR server har bir wordlist so‘roviga bir xil so‘z — pebble — ni qaytaradigan qilib yozildi.

Natijada yangi parol oldindan ma’lum bo‘ldi:

pebble pebble pebble pebble pebble pebble

Jarayonda oltita PIR so‘rovi qayta ishlangani kuzatildi. So‘ng skript Warmup User nomidan login qilib, akkauntdagi yozuvlarni o‘qidi.

4. Flagni olish va tasdiqlash

Login muvaffaqiyatli bo‘lgach, parol menejeridagi warmup flag yozuvi ochildi va quyidagi flag topildi:

PP{yOu_4r3_7h3_5rv3r_n0w::ycF1hSK_GsIN}

Flag PP{...} formatida CTF platformasiga yuborildi. Dastlabki urinishda qabul qilinmagan holat bo‘lgan, ammo keyingi yuborishda platforma “Nice! Flag accepted!” deb tasdiqladi.

Zaiflikning sababi

Bu yerda oddiy parol taxmin qilish usuli ishlatilmadi. Muammo ishonchsiz wordlist URL va autentifikatsiyalanmagan PIR javobi edi. Ilova kriptografik javobning tuzilishini tekshirardi, lekin u albatta ishonchli wordlist serveridan kelganini kafolatlamasdi. Shuning uchun parol yaratish jarayonidagi so‘zlarni nazorat qilish mumkin bo‘ldi.

Xulosa

Diceware topshirig‘ida birinchi — Warmup — flag olindi. Arxivdagi kodni o‘rganish, Python orqali mos PIR javobini yaratish va VPN orqali CTF muhitida sinash yechimga olib keldi.

Muhim: bu write-up faqat topilgan birinchi flagga tegishli. User va Admin flaglari ushbu sinovda topilmagan.

Категория: Cryptography / Web
Этап: Warmup (флаг 1)
Статус: Решено и принято на платформе CTF
Флаг: PP{yOu_4r3_7h3_5rv3r_n0w::ycF1hSK_GsIN}

Задание

Был выдан архив crypto.diceware.zip. В нём были менеджер паролей на Python/Flask, модуль PIR (Private Information Retrieval) на Rust и код сервера словаря. Цель — войти в аккаунт Warmup User и получить запись warmup flag внутри него.

OSINT-картинки в этом задании не было: главными уликами были исходный код из ZIP и запущенный сервис CTF.

Инструменты

  • ZIP-архив и исходный код: web/app/app.py, web/app/diceware.py, inspire/src/pir.rs, wordlist_server/src/main.rs
  • Termux — доступ к терминалу с телефона
  • Ubuntu VPS + WireGuard — подключение к сети CTF
  • Python 3 — сервер PIR-ответов и автоматическая проверка
  • HTTP-запросы — сброс пароля и проверка входа

Решение

1. Поиск слабого места в коде

В web/app/app.py был эндпоинт POST /reset_password. Он принимал username и wordlist и создавал новый пароль так:

new_password = generate_password(
    CLIENT_USERS,
    str(request.form.get("wordlist", DEFAULT_WORDLIST))
)

Сброс пароля для FlagUser был запрещён, а для Warmup User — разрешён.

web/app/diceware.py отправлял POST на адрес wordlist из запроса и превращал полученный PIR-ответ в слова пароля. Главная ошибка: адрес wordlist контролировал пользователь, а сервис доверял криптографическому ответу, пришедшему с него.

2. Управление PIR-ответом

Простого текстового ответа pebble было недостаточно. Сервер ждал правильный Content-Type и зашифрованный ответ в формате PIR.

Поэтому я написал скрипт diceware_pir_solution.py. Он извлекал модуль (n) открытого ключа Paillier из входящего PIR-запроса и собирал подходящий зашифрованный ответ, кодирующий слово pebble. Ответ сериализовался в формате postcard, который ожидает клиент на Rust.

У скрипта было два режима:

python3 diceware_pir_solution.py serve --word pebble --port 9000

Затем во втором терминале — для сервиса CTF, каким он был в тот момент:

python3 diceware_pir_solution.py solve \
  --base http://10.83.9.64:8081 \
  --callback http://10.82.1.33:9000/ \
  --word pebble

Примечание: IP-адреса относились к сессии CTF и позже могут измениться.

3. Пароль известен заранее

generate_password() составлял каждый пароль из 6 слов. Наш поддельный PIR-сервер на каждый запрос словаря возвращал одно и то же слово — pebble.

В итоге новый пароль был известен заранее:

pebble pebble pebble pebble pebble pebble

В процессе было обработано шесть PIR-запросов. Затем скрипт вошёл как Warmup User и прочитал записи аккаунта.

4. Получение и подтверждение флага

После успешного входа открылась запись warmup flag в менеджере паролей, и в ней был флаг:

PP{yOu_4r3_7h3_5rv3r_n0w::ycF1hSK_GsIN}

Флаг был отправлен на платформу CTF в формате PP{...}. Первая попытка не была принята, но при следующей отправке платформа подтвердила: «Nice! Flag accepted!».

Причина уязвимости

Подбор пароля здесь не использовался. Проблема была в недоверенном адресе wordlist и неаутентифицированном PIR-ответе. Приложение проверяло структуру криптографического ответа, но не гарантировало, что он пришёл с доверенного сервера словаря. Поэтому можно было управлять словами, из которых создаётся пароль.

Итог

В задании Diceware решён первый флаг — Warmup. К решению привели изучение кода из архива, создание подходящего PIR-ответа на Python и проверка через VPN в среде CTF.

Важно: этот райтап касается только первого флага. Флаги User и Admin в этой попытке найдены не были.

The challenge

We were given the crypto.diceware.zip archive. It contained a Python/Flask password manager, a PIR (Private Information Retrieval) module written in Rust, and the code of a wordlist server. The goal was to log in to the Warmup User account and get the warmup flag entry stored in it.

This challenge had no OSINT image: the main evidence was the source code in the ZIP and the running CTF service.

Tools used

  • ZIP archive and source code: web/app/app.py, web/app/diceware.py, inspire/src/pir.rs, wordlist_server/src/main.rs
  • Termux — terminal access from the phone
  • Ubuntu VPS + WireGuard — connection to the CTF network
  • Python 3 — PIR response server and automated testing
  • HTTP requests — password reset and login check

Solution

1. Finding the weak spot in the code

web/app/app.py had a POST /reset_password endpoint. It took username and wordlist values and generated a new password like this:

new_password = generate_password(
    CLIENT_USERS,
    str(request.form.get("wordlist", DEFAULT_WORDLIST))
)

Resetting the password was forbidden for FlagUser, but allowed for Warmup User.

web/app/diceware.py sent a POST to the wordlist URL from the request and turned the PIR response it got back into password words. The key flaw: the wordlist URL was controlled by the user, and the service trusted the cryptographic response that came back from it.

2. Controlling the PIR response

A plain-text pebble response was not enough. The server expected the right Content-Type and an encrypted response in PIR format.

So I wrote the diceware_pir_solution.py script. It extracted the Paillier public key modulus (n) from the incoming PIR query and built a matching encrypted response that encodes the word pebble. The response was serialized in the postcard format that the Rust client expects.

The script had two modes:

python3 diceware_pir_solution.py serve --word pebble --port 9000

Then, in a second terminal, against the CTF service as it was at that time:

python3 diceware_pir_solution.py solve \
  --base http://10.83.9.64:8081 \
  --callback http://10.82.1.33:9000/ \
  --word pebble

Note: the IP addresses belonged to the CTF session and may change later.

3. Knowing the password in advance

generate_password() built every password from 6 words. Our fake PIR server returned the same word, pebble, for every wordlist request.

So the new password was known in advance:

pebble pebble pebble pebble pebble pebble

Six PIR requests were processed during the run. Then the script logged in as Warmup User and read the entries in the account.

4. Getting and confirming the flag

After a successful login, the warmup flag entry in the password manager opened and showed this flag:

PP{yOu_4r3_7h3_5rv3r_n0w::ycF1hSK_GsIN}

The flag was submitted to the CTF platform in PP{...} format. The first attempt was not accepted, but on the next submission the platform confirmed it with "Nice! Flag accepted!".

Why it was vulnerable

No password guessing was used here. The problem was the untrusted wordlist URL and the unauthenticated PIR response. The app checked the structure of the cryptographic response, but did not make sure it came from a trusted wordlist server. That made it possible to control the words used to generate the password.

Summary

In the Diceware challenge the first flag, Warmup, was solved. Studying the code from the archive, building a matching PIR response in Python and testing through the VPN in the CTF environment led to the solution.

Important: this writeup covers only the first flag. The User and Admin flags were not found during this attempt.
